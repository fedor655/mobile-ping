API

(всё отдаётся в UTF-8, тела запросов — JSON)

Как это работает

Проверка создаётся одним запросом и выполняется асинхронно: агент на устройстве, которое подключается к Wi-Fi, раздаваемому с телефонов, забирает её из очереди, по очереди обходит точки и присылает результаты. Поэтому POST /api/jobs возвращается сразу, а результат нужно забирать по идентификатору.

Обход двух телефонов занимает примерно полторы минуты. Опрашивать чаще раза в 2–3 секунды смысла нет.

Публичные ручки

POST/api/jobs

Создать проверку. Возвращает 201 и номер.

curl -X POST __ORIGIN__/api/jobs \
  -H 'Content-Type: application/json' \
  -d '{
    "targets": "facebook.com\nya.ru\n1.2.3.4:8443",
    "ports": "443,80",
    "icmp_count": 4,
    "note": "зачем проверяли",
    "devices": null
  }'

{"job_id": "3b87409cca8c", "num": 7, "url": "/j/3b87409cca8c"}
targetsстрока с переносами или массив. Допустимо 1.2.3.4, example.com, host:port, ссылка (возьмётся только хост). До 100 штук. Обязательное.
portsTCP-порты через запятую, до 6. По умолчанию 443,80. Порт, указанный прямо в цели, заменяет этот список для неё.
icmp_countпакетов на цель, 1–10, по умолчанию 4.
noteпроизвольная пометка, до 200 символов.
devicesмассив имён устройств или null — использовать все.
GET/api/jobs/<id>

Состояние и результаты. Поле status: queued → running → done либо failed. Пока идёт работа, заполненные устройства уже видны — можно показывать прогресс. 

{
  "id": "3b87409cca8c", "num": 7, "status": "done",
  "created_at": 1789883000.1, "finished_at": 1789883086.4,
  "targets": ["facebook.com", "ya.ru"], "ports": [443, 80],
  "devices": [
    {"device": "билайн №1", "operator": "билайн", "ssid": "i",
     "status": "done", "signal": "93%",
     "local_ip": "10.188.76.97",      // выдал телефон по DHCP
     "egress_ip": "81.9.73.12",       // как нас видят снаружи
     "egress_info": "PJSC Vimpelcom · Russia",
     "egress_ok": 1,                  // 0 = мобильный выход НЕ подтверждён
     "started_at": 1789883001.0, "finished_at": 1789883021.0, "error": null}
  ],
  "results": {
    "билайн №1": {
      "facebook.com": {
        "resolved_ip": "57.144.248.1",
        "icmp_sent": 4, "icmp_recv": 4,
        "rtt_min": 170.0, "rtt_avg": 182.0, "rtt_max": 201.0,
        "icmp_status": "ok",
        "tcp": [
          {"port": 443, "ok": true, "ms": 117.0,
           "tls": false, "tls_error": "TLS без ответа (молча режут)"},
          {"port": 80, "ok": true, "ms": 137.0}
        ],
        "error": null
      }
    }
  },
  "logs": [{"ts": 1789883001.0, "device": "билайн №1", "text": "подключён…"}]
}

Главное поле — tls. Российский DPI обычно пропускает TCP-соединение и рвёт его уже на ClientHello, поэтому "ok": true у порта 443 сам по себе ничего не доказывает. Блокировка — это tls: false при открывшемся TCP.

egress_ok: 0 означает, что агент не смог подтвердить выход через мобильную сеть. Такие цифры нельзя выдавать за замер с оператора.

GET /api/jobs/<id>/export.csv

Та же проверка плоской таблицей: одна строка на (устройство, цель, порт), разделитель ;, UTF-8 с BOM. Длинный формат выбран намеренно — читается pandas и Excel без подготовки, колонки не разъезжаются при смене числа портов. 

import pandas as pd
df = pd.read_csv("__ORIGIN__/api/jobs/<id>/export.csv", sep=";")
df[df.verdict == "blocked"][["device", "target", "tls_error"]]

Колонка verdict — готовый итог по цели: ok · blocked (TCP открыт, TLS сорван) · no_icmp (жив по TCP, но режет ping) · icmp_only · down · error.

GET/api/jobs

Последние 50 проверок: номер, время, статус, цели.

GET/api/agents

Агенты и их устройства — отсюда берутся имена для поля devices. online означает, что агент отмечался в последние две минуты.

GET/api/whoami

Внешний IP того, кто спрашивает. Этим агент и проверяет, что замер уходит через мобильную сеть.

Ручки агента

Требуют заголовок Authorization: Bearer <токен> (лежит на сервере в /etc/mobile-ping.env). Нужны только самому агенту — для получения результатов они не требуются.

GET /api/agent/poll?agent_id=… взять задание из очереди; отдаётся не более одного раза
POST /api/agent/hello отметиться и сообщить список устройств
POST /api/agent/jobs/<id>/device результаты одного телефона и строки журнала
POST /api/agent/jobs/<id>/complete закрыть задание

Ошибки

Неуспех — это код 4xx/5xx и тело {"error": "по-русски, что не так"}. Разбирать текст не нужно, он для человека.

400кривой адрес, порт не число, целей нет
401нет или неверен токен агента
404такой проверки нет

Отдельно: задание может завершиться со status: "failed" — это не ошибка HTTP, а результат. Например, агент не отвечал 30 минут.
